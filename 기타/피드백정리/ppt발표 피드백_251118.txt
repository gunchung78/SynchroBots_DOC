SynchroBots 통합 피드백 정리
1️⃣ 발표 자료 구조 & 구성 관련

발표 흐름이 논리적이어서 인상적이었으나, 더욱 강화 필요

대제목·중제목에 번호 적용 → 청자의 흐름 유지에 도움

결론 먼저 제시 후 과정 설명 (Top-down 구조)

"문제 → 원인 → 해결 → 결과" 흐름이 중요

반드시 개선 전/후 비교 데이터 포함 (수치·그래프·표)

WBS는 대·중분류만 시각적으로 간단히

프로젝트 목표와 진행 이유(전망) 명확히 제시한 점은 좋음

2️⃣ 아키텍처 / 다이어그램 관련
가장 많이 받은 공통 피드백

“다이어그램을 제대로 이해하지 못했다 / 잘 보이지 않는다”

하드웨어 아키텍처 / 소프트웨어 아키텍처 분리

Flowchart가 아니라 Component Diagram 필요

RQT Graph 활용 → Mermaid 다이어그램으로 변환

노드 간 데이터 흐름 / 통신 구조를 정리

다이어그램 내 글자 크기/배치/간격 고려

잘 안 보이는 정보는 과감히 제거 또는 통합

질문 없이도 이해 가능한 수준까지 설명 보강

3️⃣ 문제 인식 & 개선 설명 방식

단순 문제 나열이 아니라:
문제 → 원인 → 해결 → 근거 → 결과 구조 필요

"개선했다"면 정량 데이터 반드시 필요

로직·알고리즘 변경 시 → 왜 적용했는지 이유 필수

적용 파라미터 변경 시 → 무엇을 어떻게 왜 바꿨는지 기록

다중 목표(Multi Goal) 활용 내용 부족 → 반영 필요

4️⃣ 알고리즘 & 기술 설명
공통 지적:

“설명은 있는데, 이해가 어렵다 / 근거가 없다”

Sudo code or Flowchart 중 하나만 명확하게

글씨 너무 작지 않게 → 발표용으로 재정리 필요

새로운 알고리즘 적용 시 관련 이론 반드시 준비

OpenCV / Vision / Pose 계산 → 왜 필요한지 코멘트 포함

기술 설명은 다음 연결 필수:

어떤 문제를 해결하기 위해

이 알고리즘을 사용했고

어떤 효과를 얻었는가?

5️⃣ 이미지·영상·데모 활용

이미지 넣을 때 캡션 필수

“이 사진은 무엇을 보여주는가?”

영상도 마찬가지 → 실행 전 무슨 영상인지 표시

데모 시나리오 이미지화 매우 긍정적 (계속 유지할 것)

“설명 없이 복붙한 코드/사진”은 전달이 안 됨

시각 요소는 "궁금증 → 해소" 흐름 유도

6️⃣ 일정 및 협업 방식 관련

Google Sheet 기반 협업은 장점 — 계속 유지

다만 발표에서는 전체 틀만 보여주면 충분

프로젝트 Review 문서화 필요 → 회고 시 재활용 가능

7️⃣ 팀별 세부 피드백 요약
🔧 AGV 관련

평균 이상이었고 SynchroBots는 더 높은 평가

State Machine 활용 필요

SLAM/Navigation 성능 변화 → 수치로 비교

맵 이미지와 실제 위치 오차 → 같이 제시

🤖 RobotArm 관련

문제 인식은 좋았으나 해결 방안 설명 부족

Photo Sensor 보정 등은 "왜, 어떻게"를 더 명확히

Vision 회전 픽업 설명은 더 쉽고 시각적으로

📌 개선 방향 요약 (바로 적용 가능)
항목    개선 포인트
구조    결론 → 과정 구조 / 넘버링 추가
아키텍처    HW / SW 분리 + Node 연결 명시
다이어그램    Flowchart → Component Diagram로 교체
문제 정의    “문제 → 원인 → 해결 → 데이터” 방식
알고리즘    Sudo code/Flowchart 중 하나 집중 + 글자 크게
데이터    개선 수치 강조 (전후 비교 필수)
이미지    캡션 강제 적용 + 의미 설명
WBS    큰 카테고리만, 깔끔하게
시나리오    전체 흐름을 한 장짜리로 시각화
