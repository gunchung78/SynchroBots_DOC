최종 시나리오

1.  AMR 미션 시작 물체 두는 장소(하역장) 도착(이때 물건은 불량 1 정상 2를 가정)
	
2.  하역 시작 이때 통신으로 web에서 amr_mission_state({"status": "UNLOADING"}) 을 전달

3.  WEB - 통신 전달 받을 시 PLC - ready_state({"state": "c_move"})
	3-1. PLC 컨베이어 동작 시 plc_control_state(PLC컨베이어 상태데이터) 읽기 및 mission_plc_logs테이블에 log저장

4.  물체가 센서 1(Anomaly)에 닿여서 비전 체크 진행(set_conveyorSensor_check) 체크 후 
	PLC에 OK_NG_Value({"Anomaly" : true}), AMR에 amr_go_move({"move_command" : "un_loading"}) 전달
	(*2~4을 물체가 다 하역할때까지반복)
	
5.  AMR - amr_go_move({"move_command" : "UNLOADING"}) 받다 물체를 다 하역한게 체크되면 자체적으로 go_home 위치로 이동(별도 통신 x)
	PLC - 기존 시나리오 대로 OK_NG_Value값에 따라 물체를 분류(컨베이어는 계속 구동)

6.  센서 2(Joint)에 물체가 체크 될 시
	6-1. PLC - WEB으로 robotarm_sensor_check 전송 및 컨베이어 정지
	6-2. WEB - AMR amr_go_move({"move_command" : "pick_up_zone"}), ARM arm_go_move({"move_command" : "go_home"}) 전송
	
7.  AMR 픽업존 도착 시 
    7-1. AMR - WEB에 amr_mission_state({"status": "PICK"}) 전송
    7-2. WEB - ARM arm_go_move({"move_command" : "mission_start"}) 전송
  
8.  ARM 미션 시작
	8-1. ARM 물체 jointDetection 작업 진행 및 결과값 DB mission_camera_logs 저장
	8-2. 이 후 도출된 값을 이용하여 물체 픽업 ->  AMR에 적재 - 해당 로그 DB mission_robotarm_logs에 반드시 저장 필요
	8-3. 물체가 쌓일 때 WEB에 arm_place_single 전송
	8-4. WEB - PLC에 ready_state({"state": "c_move"}) 전달하여 컨베이어 동작
	* 8-1 ~ 8-4의 동작을 반복하여 모든 하역품들 처리
	8-5. 모든 물체의 적재를 완료하면 WEB으로 arm_place_completed 전송
	
9.  WEB arm_place_completed 전달 받을 시 
	9-1. mission_robotarm_logs에 적재된 로그 확인하여 AMR에 amr_go_positions({"object_info": ["ESP32", "MB102", "L298N"]}) 형식으로 전달

10. AMR amr_go_positions 전달 받을 시
	10-1. 전달받은 순서에 맟게 3개의 골 위치로 이동(이때마다 미션로그 저장, 필요)
	10-2. 물체 운송 완료 후 WEB에 amr_mission_state({"status": "DONE"}) 전달
	10-3. WEB은 amr_mission_state({"status": "DONE"}) 받으면 바로 amr_go_move({"move_command" : "go_home"}) 전송
	
완료
	
	
	
** 각 장비들을 미션 시작 시 부터 이벤트에 맟춰 로그 저장
	* amr, arm의 경우 mission_logs에 로그 저장 시작 이때 mission_logs INSERT하여 KEY값 체크 하여
	* 세부 log를 각각 mission_amr_logs, mission_robotarm_logs에 저장한다.
	* PLC는 센서 1,2 체크, 컨베이어 동작 정지 시 단건으로 mission_plc_logs에 저장한다.
	
** AMR은 주기적으로 amr_state 위치 값 저장
